实验三：基于内容的电子邮件过滤系统——对话记忆总结

一、实验目标与总体要求
本次实验三的主题是“基于内容的电子邮件过滤”。实验要求实现一个简单的邮件过滤系统，能够完成正常邮件和垃圾邮件两类语料划分，并能在邮件服务器端自动识别、监控、处理甚至拦截垃圾邮件。

本项目最终定位为 MailGuard 邮箱系统：
1. 多个用户通过网页邮箱系统登录、写邮件、查看邮箱。
2. 邮件发送必须严格使用 SMTP 协议。
3. 客户端只负责写邮件和发送邮件，不在客户端判断垃圾邮件。
4. 服务端在 SMTP 的 DATA 阶段接收完整邮件内容。
5. 服务端解析邮件主题和正文。
6. 服务端调用朴素贝叶斯模型或关键词兜底规则计算垃圾概率。
7. 根据垃圾概率将邮件投递到：
   - inbox：正常收件箱
   - spam：垃圾箱
   - blocked：拦截箱

最终实现效果：
正常邮件进入 inbox；
可疑垃圾邮件进入 spam；
高危垃圾邮件进入 blocked。

二、项目核心文件
项目主要由三个 Python 文件组成：

1. client.py
功能：
- Streamlit 邮箱前端
- 用户登录、注册
- 写邮件
- 使用 smtplib.SMTP 发送邮件
- 查看服务端保存的 inbox、spam、blocked 邮件
- 显示邮件主题、收件人、时间、正文等信息

2. server.py
功能：
- 自定义 SMTP 服务端
- 监听 0.0.0.0:2525
- 支持 EHLO/HELO、AUTH、MAIL FROM、RCPT TO、DATA、QUIT 等 SMTP 命令
- 校验用户账号密码
- 判断收件人是否为本地系统用户
- 接收邮件内容
- 解析邮件主题和正文
- 调用模型或关键词规则计算垃圾概率
- 保存邮件到 inbox、spam、blocked
- 记录服务端日志 logs/server.log

3. train_model.py
功能：
- 读取 TREC06C 邮件数据集
- 清洗文本
- 中文分词
- 训练朴素贝叶斯垃圾邮件分类模型
- 输出 Accuracy、Precision、Recall、F1
- 保存 model.pkl，供 server.py 加载使用

三、SMTP 重点说明
SMTP 是 Simple Mail Transfer Protocol，即简单邮件传输协议，是邮件发送和转发的标准协议。

在本实验中，SMTP 的作用是“邮件传输通道”：
用户在网页端写邮件；
client.py 调用 smtplib.SMTP；
连接 server.py 提供的 SMTP 服务；
通过 SMTP 命令把邮件投递给服务端；
服务端收到完整邮件后再判断是否垃圾邮件。

本系统中的 SMTP 命令流程：
1. EHLO / HELO：客户端向服务端打招呼，开始 SMTP 会话。
2. AUTH：用户认证，验证邮箱账号和密码。
3. MAIL FROM：声明发件人。
4. RCPT TO：声明收件人。
5. DATA：传输邮件主题、正文等完整内容。
6. QUIT：结束 SMTP 会话。

关键点：
垃圾邮件判断发生在服务端 DATA 阶段之后。
客户端不判断垃圾邮件。
这能够体现“服务端自动识别、监控、处理、拦截”的实验要求。

四、端口与网络访问
系统涉及两个端口：

1. 8501
- 网页邮箱端口
- 由 Streamlit / client.py 提供
- 用户浏览器访问此端口使用邮箱系统

2. 2525
- SMTP 邮件服务端口
- 由 server.py 提供
- client.py 通过 smtplib.SMTP 连接此端口发送邮件

示例：
网页访问地址：
http://服务端IP:8501

SMTP 发送地址：
127.0.0.1:2525
或者在不同部署方式下使用 服务端IP:2525

五、三人演示部署方式
推荐三人演示方式：

同学1：服务端电脑
- 运行 server.py
- 运行 client.py / Streamlit 网页服务

同学2：发件人
- 浏览器访问服务端网页
- 登录发件人账号
- 发送正常邮件或垃圾邮件

同学3：收件人
- 浏览器访问服务端网页
- 登录收件人账号
- 查看 inbox、spam、blocked 分类结果

推荐运行结构：
服务端电脑同时运行：
1. python server.py
2. streamlit run client.py --server.address 0.0.0.0 --server.port 8501

其他同学浏览器访问：
http://服务端IP:8501

如果服务端电脑查到 WLAN IPv4 地址为 10.29.114.115，则其他人访问：
http://10.29.114.115:8501

注意：
如果三个人都访问服务端电脑上的 Streamlit 网页，那么页面内部 SMTP Host 可以保持 127.0.0.1，SMTP Port 保持 2525。
原因是 smtplib.SMTP 实际执行在服务端电脑上，127.0.0.1 指的是服务端电脑自己。

六、服务端 IP 使用说明
服务端电脑用 ipconfig 查询 IP。

需要使用当前正在联网的网卡 IPv4 地址。
例如截图中出现：
- 192.168.138.1
- 192.168.220.1
- 10.29.114.115

其中 10.29.114.115 是 WLAN 无线局域网适配器地址，应作为服务端 IP 给其他同学访问。
192.168.138.1、192.168.220.1 多半是虚拟网卡地址，不适合作为同学访问地址。

- model.metrics.json

3. 启动 SMTP 服务端：
python server.py

成功标志：

4. 启动网页邮箱：
streamlit run client.py --server.address 0.0.0.0 --server.port 8501

5. 其他同学访问：
http://服务端IP:8501

八、账号管理
系统账号保存在 smtp_users.json 中。
用户可以通过前端注册，也可以手动在 smtp_users.json 中添加账号。

示例账号：
sender@bupt.edu.cn / 123456
receiver@bupt.edu.cn / 123456
admin@bupt.edu.cn / 123456

用户使用真实邮箱格式也可以，例如：
jyfjch609794956@163.com
但注意该系统是本地实验邮箱系统，不是连接真实 163 邮箱服务器。
只要该账号存在于 smtp_users.json，就可以登录和发送系统内邮件。

九、邮件分类逻辑
服务端对邮件主题和正文进行组合：
Subject + Body

然后进行：
1. MIME 解析
2. HTML 标签清理
3. 中文分词
4. 特征提取
5. 朴素贝叶斯概率计算
6. 分类投递

分类阈值：
垃圾概率 < 70%：
进入 inbox，状态 clean

70% ≤ 垃圾概率 < 90%：
进入 spam，状态 spam

垃圾概率 ≥ 90%：
进入 blocked，状态 blocked

如果没有 model.pkl：
系统启用关键词兜底规则。
关键词包括：
中奖、大奖、百万、点击、链接、验证码、银行卡、密码、领取、转账、贷款、博彩、投注等。

十、训练模型说明
train_model.py 使用 TREC06C 邮件数据集训练朴素贝叶斯模型。

流程：
1. 读取 trec06c/full/index
2. 根据 index 找到邮件文件
3. 区分 spam 和 ham
4. 清洗 HTML 和特殊符号
5. 使用 jieba 分词
6. 过滤单字、纯数字等无效词
7. 统计垃圾邮件和正常邮件词频
8. 计算先验概率和条件概率
9. 使用拉普拉斯平滑
10. 划分训练集和验证集
11. 输出 Accuracy、Precision、Recall、F1
12. 保存 model.pkl

验收时可说明：
该模型是实验二文本分类方法在实验三邮件过滤中的应用。

十一、常见问题与解决
1. 只启动 server.py，其他人能访问 http://服务端IP:8501 吗？
不能。
server.py 只提供 SMTP 服务，端口是 2525。
网页邮箱由 client.py / Streamlit 提供，端口是 8501。
必须同时启动：
python server.py
streamlit run client.py --server.address 0.0.0.0 --server.port 8501

2. SMTP Host 和 SMTP Port 有什么用？
SMTP Host 是邮件服务端地址。
SMTP Port 是 SMTP 服务端口。
在本系统中，SMTP Port 通常是 2525。
如果网页服务和 SMTP 服务都在服务端电脑运行，SMTP Host 可填 127.0.0.1。
如果每台电脑都单独运行 client.py，则 SMTP Host 应填服务端 IP，但这种方式不推荐。

3. 投递失败：(501, b'Invalid sender address')
原因：
smtplib 发送的 MAIL FROM 命令可能带有 size 参数，例如：
MAIL FROM:<xxx@163.com> size=1234

原服务端解析不完整，导致地址解析失败。
解决：
在 server.py 中添加 parse_smtp_address(argument, prefix) 函数，兼容：
MAIL FROM:<user@example.com>
MAIL FROM:<user@example.com> size=1234
RCPT TO:<user@example.com>

然后 handle_mail 和 handle_rcpt 使用 parse_smtp_address 解析地址。

4. 其他电脑无法访问网页
检查：
- 三台电脑是否在同一个局域网
- 是否访问 http://服务端IP:8501，而不是 127.0.0.1
- 服务端是否使用 --server.address 0.0.0.0 启动
- Windows 防火墙是否放行 8501 和 2525
- 可以用 ping 服务端IP 测试网络连通

十三、验收讲解稿
可以直接这样讲：

本实验实现了一个基于内容识别的电子邮件过滤系统。系统采用客户端/服务端结构，前端使用 Streamlit 实现邮箱界面，服务端使用 socketserver 实现 SMTP 邮件服务器。

用户在网页端编写邮件后，客户端并不直接保存邮件，而是通过 Python 的 smtplib.SMTP 模块连接 SMTP 服务端，按照 EHLO、AUTH、MAIL FROM、RCPT TO、DATA、QUIT 等 SMTP 命令完成邮件投递。服务端在 DATA 阶段接收到完整邮件内容后，解析邮件主题和正文，对文本进行清洗、分词和特征提取，然后调用朴素贝叶斯模型计算垃圾邮件概率。

根据计算得到的风险值，系统将邮件分为正常邮件、垃圾邮件和高危拦截邮件三类。正常邮件保存到 inbox，垃圾邮件保存到 spam，高危邮件保存到 blocked。收件人登录邮箱后，可以看到邮件的分类结果、风险值和投递目录。

本系统体现了邮件过滤系统的核心流程：SMTP 传输、服务端接收、内容解析、模型判断、分类投递和结果展示。

十四、老师可能提问与回答
1. 是否严格使用 SMTP？
回答：
是。客户端通过 smtplib.SMTP 连接服务端 2525 端口，服务端实现了 EHLO、AUTH、MAIL FROM、RCPT TO、DATA、QUIT 等 SMTP 命令流程。

2. 垃圾邮件在哪里判断？
回答：
在服务端判断。客户端只发送邮件，不判断垃圾邮件。服务端收到 DATA 阶段的完整邮件后才进行内容识别。

3. 为什么有 inbox、spam、blocked？
回答：
这是为了体现不同处理策略。低风险进入 inbox，中风险进入 spam，高风险进入 blocked，实现识别、监控、处理和拦截。

4. 没有 model.pkl 怎么办？
回答：
系统会启用关键词兜底规则，保证实验演示可运行。正式实验中可先运行 train_model.py 训练朴素贝叶斯模型生成 model.pkl。

5. 8501 和 2525 有什么区别？
回答：
8501 是网页邮箱访问端口，由 Streamlit 提供；2525 是 SMTP 邮件服务端口，由 server.py 提供。用户操作网页使用 8501，邮件发送使用 2525。

前端整体经过多轮优化，目标是让界面更适合课堂验收和投屏演示。

主要修改方向：
1. 将界面改为浅色企业邮箱风格。

5. 删除不必要的搜索邮件、状态筛选、刷新功能。
6. 邮箱页面只保留收件箱、垃圾箱、拦截箱和统计卡片。
7. 邮件接收界面简化展示，只保留收件人、主题、时间。

9. 过滤“未知发件人”“解析失败”“sender发给receiver”等异常系统邮件。
10. 后续针对邮件详情比例不均衡问题，建议让邮件卡片宽度适中、元信息紧凑、正文区域自适应高度，避免过多空白。
